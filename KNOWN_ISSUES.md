# Известные проблемы

## Высокое потребление памяти в tail при большом числе файлов

Если при слежении за большим числом журналов растёт потребление памяти,
проверьте `FileLog.Open` в [onectechlogparser.go](onectechlogparser.go).
На каждый открытый файл он выделяет 64 КиБ под буфер чтения `f.reader`
и 64 КиБ под буфер сборки события `f.event`.

В режиме tail файлы остаются открытыми между опросами. Параметр `threads`
ограничивает число одновременных вызовов `Read`. При 1 000 отслеживаемых
файлов начальные буферы занимают около 125 МиБ даже при `threads=4`.

### Пожелание по оптимизации

Выделять память под `f.event` по мере роста записи. Проверить возможность
переиспользовать буферы чтения между файлами, ограничив их число значением
`threads`. Между опросами сохранять позицию чтения, данные незавершённого
события и фрагмент строки, полученный перед EOF.
