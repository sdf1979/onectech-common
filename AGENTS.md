# Работа с onectech-common

`onectech-common` — Go-библиотека, которую другие проекты подключают для работы с технологическим журналом (ТЖ) 1С. Путь модуля — `github.com/sdf1979/onectech-common`, имя корневого пакета — `onectechcommon`.

При изменениях учитывайте совместимость с кодом потребителей. Экспортируемые типы, функции и методы могут использоваться в других проектах, даже если поиск по этому репозиторию не находит вызовов.

## Чтение журнала

- `FileWatcher.Run` в `onectechlogwatcher.go` рекурсивно находит файлы `.log` и возвращает канал `*EventLog`. Файлы читаются параллельно, поэтому общий порядок событий из разных файлов не гарантирован. Канал закрывает сам `FileWatcher`.
- `FileLog` в `onectechlogparser.go` собирает многострочные записи. Дату и час он берёт из первых восьми символов имени файла в формате `YYMMDDHH` по местному времени. Минуты, секунды и микросекунды берутся из записи. При изменении чтения проверьте разовый проход по файлу с UTF-8 BOM и слежение за дописываемым файлом, где EOF может прийти посреди строки.
- `NewEvent` в `eventlog.go` сохраняет порядок и повторы полей. Для повторяющегося `p:processName` метод `Value` возвращает первое значение, для остальных ключей — последнее. При изменении разбора проверяйте записи с повторяющимися ключами, запятыми и переносами строк внутри кавычек. Имена событий и полей собраны в `const.go`.

## Анализ и агрегация

- `Analysis.Process` в `analysis.go` читает канал до закрытия, связывает события по `ThreadSessionKey` и затем вычисляет итоговые показатели вызовов и запросов. При изменении обработки контекста проверяйте последовательность событий одного потока и сеанса. Для группировки SQL-событий `DBMSSQL` и `DBPOSTGRS` используется `QueryNormalizer.Digest` из `querynormalizer.go`.
- Для нового счётчика дерева реализуйте интерфейс `aggregator.Aggregator` по образцу `aggregator/counter.go`. Метод `Node.Insert` применяет одно обновление к корню и каждому узлу пути, поэтому `Clone` должен возвращать независимый счётчик с нулевыми значениями. Метод `Calculate` получает агрегатор родителя, у корня это `nil`.
- `Store` в `store.go` использует SQLite для анализа тайм-аутов блокировок по событиям `TTIMEOUT`, `TLOCK` и записям `SDBL` с `Func=BeginTransaction`. Запускайте проверки хранилища в отдельном временном каталоге. `OpenNew()` открывает `tmp.db` в текущем каталоге и пересоздаёт таблицы, удаляя прежние данные. Вызывайте `Close()` после записи, чтобы завершить транзакцию и создать индексы.

## HTML-отчёты

`HTMLBuilder` в `htmlbuilder.go` собирает страницу, а `htmltable.Render` строит таблицу по дереву `Node`. В `Node.Walk` родитель посещается до дочерних узлов. Дети обходятся по убыванию `Score()`, при равенстве — по возрастанию ключа. Сохраняйте этот порядок, поскольку рендерер использует его для привязки строки к родителю.

Заголовки колонок формируются из экспортируемых полей агрегатора с учётом тегов `json`. При изменении разметки сверяйте классы и атрибуты `data-*` с `htmltable/table.js` и `htmltable/table.css`. Оба файла встраиваются через `//go:embed` в `htmltable/assets.go`.

## Проверка изменений

Версия Go указана в `go.mod` (сейчас `1.26.4`). Форматируйте изменённые Go-файлы командой `gofmt -w`, передавая ей пути к файлам. Команды сборки и проверки запускайте из корня модуля.

```sh
go build ./...
go test ./...
go vet ./...
```

Сейчас в репозитории нет файлов `*_test.go`. Сообщение `[no test files]` означает, что пакет скомпилировался, но его поведение тестами не проверялось.
